Installation

Requirements

Linux x86_64. A bash shell and a Fortran compiler are needed to build qvasp from source; a binary release needs neither.

To build from source: ifort (preferred) or gfortran, and the static spglib 2.7.0 library that the Makefile links for symmetry analysis.

To run: nothing. Since v3.0 qvasp is a single executable: all 88 commands are compiled into one binary, and the python / numpy / pymatgen / MDAnalysis dependencies of the old versions are gone. The only files qvasp reads at run time are the INCAR templates, the POTCAR library and the showstatus script, and all three live in the USERDefine/ directory next to the executable.

Download

Download the installation package from SourceForge qvasp package . At the release page you find a compressed tarball (tar zxvf qvasp-v3.01.tar.gz) containing:

qvasp-v3.01
|---qvasp                  the single executable
|---install.sh
|---uninstall.sh
|---Makefile
|---src/                   Fortran sources
|---build/                 object files
|---USERDefine/
|   |---INCAR/             17 INCAR templates (customizable)
|   |---POTCAR/            PAW library  (you provide this)
|   |---TooLs/             user-defined tools
|   |---showstatus/        job-status scripts
|   |---vasp.pbs           job script for Torque / PBS
|   |---vasp.sge           job script for SGE
|---documents/
|---update.log

Installation

1. Upload and extract the package

> tar -zxvf qvasp-v3.01.tar.gz
> cd qvasp-v3.01

Note

Do not unpack the archive on Windows and copy the result over: the executable bit and the symlinks (USERDefine/POTCAR/paw_pbe) are lost.

2. Build the executable (skip this step if the tarball already contains a binary that matches your compiler and MPI)

> make

The Makefile picks ifort when it is on the PATH and falls back to gfortran; override with make FC=.... The last line of the output should be qvasp built OK. make clean removes the object files.

3. Install

> ./install.sh

The script takes an optional target directory (./install.sh /opt/qvasp) and defaults to the directory it lives in. It

  • creates USERDefine/{INCAR,POTCAR,TooLs,showstatus},

  • seeds the 17 INCAR templates if the directory is empty,

  • links USERDefine/POTCAR/paw_{pbe,lda,pw91} to the PAW library it finds,

  • activates one showstatus-*.sh as showstatus.sh (torque by default — repoint the symlink to switch to slurm, sge, pbspro, …),

  • appends a marked block to ~/.bashrc (/etc/profile when run as root).

Answer yes when it asks whether to modify your profile. The block it writes looks like this:

######### qvasp-v3 #############
export PATH=/opt/qvasp:$PATH
export PATH=/opt/qvasp/USERDefine/TooLs/vtstscripts:$PATH
########### end #############

Note that there is no export qvasppath=... any more. The executable finds its own installation root (USERDefine/ beside the binary), so the variable of the v2.x releases is obsolete and setting it does nothing.

The block is written only once: install.sh greps for the marker first, so re-running it after an upgrade will not duplicate your PATH.

4. Provide the PAW potentials

qvasp does not redistribute the VASP PAW files. Put them where the program expects them:

USERDefine/POTCAR/paw_lda/
USERDefine/POTCAR/paw_pbe/
USERDefine/POTCAR/paw_pw91/

Each element needs its own directory (paw_pbe/C/POTCAR). If the library already exists elsewhere on the machine, a symbolic link per functional is enough — that is what install.sh does when it can find an older qvasp installation. Make sure the files are world-readable: a POTCAR that only you can read will fail inside somebody else’s job.

5. Adapt the job script

USERDefine/ also carries the submission templates, vasp.pbs for Torque / PBS and vasp.sge for SGE. Edit the one that matches your cluster once, before the first submission:

#PBS -N vasp6
#PBS -l nodes=1:ppn=24          # cores per job
#PBS -l walltime=860:00:00      # wall time limit
#PBS -q default                 # queue name -- must exist on your cluster
#PBS -V
#PBS -S /bin/bash

ulimit -s unlimited
ulimit -m unlimited
ulimit -c unlimited
ulimit -d unlimited

cd $PBS_O_WORKDIR
EXEC=/home/wencai/soft/vasp.6.4.2/bin/vasp_std    # absolute path of VASP
...
mpirun -np $NP $EXEC > log

Three lines decide whether the job runs at all: the queue name (qsub answers requested queue not found when it is wrong), the absolute path of the VASP executable (a bare vasp_std is not on the PATH of a compute node), and the ulimit -s unlimited that the Intel MPI build of VASP needs to avoid a segmentation fault at the first SCF step. qvasp -sub <dir> copies this file into the target folder as vasp.script and submits it.

6. Reload the shell

> source ~/.bashrc      # or open a new terminal

Uninstalling. ./uninstall.sh removes the marked block from your profile and then asks whether to delete the installation directory.

Test your installation

1. Generate a POTCAR

> qvasp -pbe C H

The POTCAR is produced successfully

Let's check it
  TITEL  = PAW_PBE C 08Apr2002
  TITEL  = PAW_PBE H 15Jun2001

If you see this, the POTCAR library is found and readable.

2. Check the job queue

> qvasp

This runs the showstatus script and prints the queue of your scheduler:

---------------------------------------------------------------------
   57834       fairchem       R    cu07     /public/home/yiwc/run1
---------------------------------------------------------------------
   57835       fairchem       Q             /public/home/yiwc/run2
---------------------------------------------------------------------

If it prints nothing, or complains, the active USERDefine/showstatus/ showstatus.sh does not match your scheduler.

3. Read the help

> qvasp -help

prints the command table. The banner tells you which version you are running:

+=================================================================================================+
|                              qvasp usage v3.01  (Author: Wencai Yi)                             |
|                      magnetic suite / optics / surfaces / freqfix  2026-11-23                   |
+=============== INCAR templates ================+=============== INCAR templates ================+
...

The complete table is reproduced on the Overview page. qvasp -help is also the authoritative list of commands: if a command is not in that table it does not exist in your build, with two documented exceptions that are kept out of the table for space reasons — qvasp -sub <dir> (submit the job script) and qvasp -d [jobid] (delete jobs).

4. Run a calculation

The shortest end-to-end test is the one in Getting Started: convert a CIF, generate the inputs, submit. It takes about a minute and touches every part of the installation (structure reading, template lookup, POTCAR lookup, scheduler script).

Upgrading from v2.x

The directory layout changed, so an in-place upgrade is not supported; install v3.01 beside the old version, test it, and remove the old one afterwards.

  • exefile/ is gone. INCAR, POTCAR, TooLs and showstatus now live under USERDefine/.

  • source-code/ and the per-command binaries are gone; there is one qvasp executable.

  • export qvasppath=... is no longer read.

  • -c2p2 was removed (-c2p reads Materials Studio CIF files as well), -it2 became -itms, and -zc became -freqfix (the old name still works).

  • The -kline / -khse / -kphonon path generator no longer needs python or pymatgen; -rdf, -msd, -hej and -mos are pure Fortran too.

See Release Notes for the complete list.
