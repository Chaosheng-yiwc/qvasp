Tutorials

Running Ways

There are 2 ways to run qvasp under command line mode:

  1. Just type qvasp -pbe C H in the terminal to generate POTCAR;

  2. echo -e "\n \n" | qvasp -bandd;

Run qvasp in Batch Mode

if one wants to run qvasp in batch mode, for example, to generate POTCAR file in several sub-olders with POSCAR:

for i in `ls -l |grep -a "^-"|awk '{print $NF}'`
do
    cd $i
        elements=`cat POSCAR|sed -n 6p`
    qvasp -pbe $elements
        echo $i "done"
    cd ..
done

if one wants to extract the specified physical quantity, for example, to read band gap in several sub-olders:

for i in `ls -l |grep -a "^-"|awk '{print $NF}'`
do
    cd $i
    bandgap=`echo -e "\n \n" | qvasp -bandd | sed -n '7p' | awk '{print $7}'`
        echo "Band gap of "  $i  " is " $bandgap
    cd ..
done

Check the queue

qvasp with no argument prints the status of your own jobs, so you do not have to remember the qstat incantation of your cluster:

> qvasp

 -------------------------------------------------------------------------------------------------------
    93016       mdm_Fe         C     cu07     /public/home/yiwc/qvasp_retest/md_Fe
 -------------------------------------------------------------------------------------------------------
    93017       mdm_Fe2        R     cu06     /public/home/yiwc/qvasp_retest/md_Fe2
 -------------------------------------------------------------------------------------------------------

The columns are the job id, the job name, the state, the node and the working directory. qvasp -showstatus is the same thing spelled out.

This is not a reimplementation of qstat: it calls a small shell script, and the script for your scheduler has to be selected once at install time. The candidates live in USERDefine/showstatus/:

showstatus-torque.sh        Torque / PBS
showstatus-pbspro.sh        PBS Pro
showstatus-slurm.sh         SLURM (squeue)
showstatus-slurm2.sh        SLURM, alternative formatting
showstatus-sge.sh           SGE / UGE
showstatus-stampede.sh      Stampede-style SLURM
showstatus-shuguang.sh      曙光
showstatus-shenzhensupercal.sh  深圳超算
showstatus-orgin.sh         template to copy when writing your own

showstatus.sh is a symbolic link to the one that is active, so switching scheduler is one command:

> cd USERDefine/showstatus
> ln -sf showstatus-slurm.sh showstatus.sh

install.sh points the link at showstatus-torque.sh by default. If your cluster is not in the list, copy showstatus-orgin.sh and edit it: the only requirement is that it prints one line per job, and that the last field of that line is the working directory.

Generate Input Files

To perform a firt principle calculation using VASP, usually one needs 4 files, INCAR,POSCAR, POTCAR and KPOINTS.

  1. INCAR contains all keywords and tells VASP what to calculate;

  2. POSCAR contains lattice parameters, atomic coordinates information,and atomic velocity information (for MD);

  3. KPOINTS, contains K-points information in the reciprocal space, at which the wave function integrates to obtain the charge density.

  4. POTCAR is a pseudo potential file, which is USPP or PAW type;

qvasp provide flexible toolkit to generate the input files for VASP.

Usually, we recommand generate POSCAR firstly.

> qvasp -c2p C.cif

KPOINTS

The generation of KPOINTS requires the exist POSCAR, the k density and lattice constant determine the KPOINTS. For self-consistent calculation, we need to prepare a KPOINTS file to specify density of K-points and the method for automatic k-mesh generation.

> qvasp -k 0.03

Then, qvasp will ask us to input KPT-Resolved Value between K-points in reciprocal cell in units of \(2\pi \times 0.03\ \mathrm{\AA}^{-1}\). And in this command, the dimension of material will be considered, the vacuum direction will be set to 1. We should note that the dimension of material may be wrong, we could revise it manually.

or

We can ignore the dimension of material via using:

> qvasp -3k 0.03

Number of K-points increases when the density of k decreases. For each direction, the number is determined by

\[N=\max \left(1,\left|\vec{b}_{i}\right| / \mathrm{density}\right)\]

where \(\vec{b}_{i}\) are the reciprocal lattice vectors. These values are rounded to the next integer greater than or equal to N. The recommend value ~0.03 (\(2\pi \times 0.03\ \mathrm{\AA}^{-1}\)) is enough for most system. This parameter is similar as the parameter KSPACING in INCAR. But the unit is different. Unit of KSPACING is \(\mathrm{\AA}^{-1}\), and the unit of qvasp is \(2\pi \times 0.03\ \mathrm{\AA}^{-1}\).

The output KPOINTS file is:

> cat KPOINTS
Auto
0
G
16 16 16
0.  0.  0.

POTCAR

The POTCAR should be generated by the element orders in POSCAR (6th line).

> qvasp -pbe C

The RECOMMENDED_POTCAR tag control whether to use recommended potentials from VASP manual (Page. 195, 2018.10.29, http://cms.mpi.univie.ac.at/vasp/vasp/Recommended_PAW_potentials_DFT_calculations_using_vasp_5_2.html).

POTCAR types:

  1. No extensions “_”

  2. _d. An extension d, treat the d semi core states as valence state.

  3. _pv or _sv. The extensions _pv and _sv imply that the p and s semi-core states are treated as valence states.

  4. _h and _s. An extension _h or_s implies that the potential is harder or softer than the standard potential and hence requires a higher or lower energy cutoff.

  5. Pseudo hydrogen. ex: H.5

  6. _GW. Used for GW calculation.

If we want to use _sv or _pv or H 1.25e pseudo potential, use command:

> qvasp -pbe Ca_sv H1.25

Then the POTCAR file is generated as:

> cat POTCAR

If we want to check the type of POTCAR, use command:

> qvasp -cp

 TITEL  = PAW_PBE Ca_sv 06Sep2000
 TITEL  = PAW_PBE H1.25 07Sep2000

The results show that the type of POTCAR is PAW_PBE, and the elements contain Ca_sv and H1.25.

The functional is chosen by the command, and all three libraries live side by side under USERDefine/POTCAR/:

> qvasp -pbe  C H     # PAW_PBE   USERDefine/POTCAR/paw_pbe
> qvasp -lda  C H     # PAW_LDA   USERDefine/POTCAR/paw_lda
> qvasp -pw91 C H     # PAW_PW91  USERDefine/POTCAR/paw_pw91

Mixing functionals inside one POTCAR is not possible – the concatenation follows the element order of POSCAR, and every element is taken from the same library.

qvasp -md         INCAR-md         molecular dynamics

qvasp -elastic    INCAR-elastic    elastic constants (IBRION = 6)
qvasp -ts         INCAR-ts         dimer / NEB transition state
qvasp -bader      INCAR-bader      Bader charge analysis
qvasp -wk         INCAR-workfunction  LVHAR = .TRUE.
qvasp -elf        INCAR-elf        electron localization function
qvasp -lobster    INCAR-lobster    COHP / COOP for LOBSTER
qvasp -partchg    INCAR-particalchg   band- and k-point-resolved partial charge

Three of them are worth a note because their templates carry tags that are easy to forget:

  • qvasp -elf sets LELF = .TRUE. and PREC = Accurate. The localization function is a real-space quantity, so a coarse FFT grid (the PREC = Normal default) shows artefacts around the nuclei; the template already switches to Accurate for you, and the comment at the end of the generated INCAR reminds you to keep it.

  • qvasp -lobster sets ISYM = -1 and LWAVE = .TRUE.. LOBSTER reads the WAVECAR and the basis information is symmetry independent, so the symmetry must be switched off and the wavefunction must be kept. The template also raises NBANDS if you uncomment that line; the comment says to use 1.5 times the default, which is what LOBSTER needs to describe the unoccupied states well.

  • qvasp -partchg writes LPARD = .TRUE. together with LSEPB, LSEPK, IBAND and KPUSE. IBAND and KPUSE are the bands and k-points whose partial charge you want, and the template leaves a comment pointing to qvasp -b, which prints the band-resolved information you need to fill them in. The file also lists the EINT (energy window) variant and the NBMOD = -3 variant as commented blocks, so you can switch approach without looking anything up.

Every one of these commands is non-interactive: it only reads the templates and writes INCAR in the current directory, so they can be scripted in a loop over many folders exactly like qvasp -pbe above.

Format Transfer

qvasp provide effective tool for files format transfer, include:

.cif to POSCAR

(support batch mode; each argument is converted separately and yields both POSCAR and <basename>.vasp)

> qvasp -c2p C.cif Pt.cif Si.cif

The same command also reads the cif files exported by Materials Studio (the _atom_site_fract_* block together with the _symmetry_equiv_pos_as_xyz / _space_group_symop_operation_xyz operators), so the former -c2p2 variant is no longer needed and has been removed in v3.

POSCAR to cif

> qvasp -p2c CONTCAR

OUTCAR to trajectory file

(the trajectory file is .arc, can be opened by Materials Studio)

> qvasp -out2arc

OUTCAR to Gauss.log

Gauss.log can be opened by Gaussian Views.

> qvasp -gauss

.castep to CHGCAR (VASP)

(density file, .castep, is the calculated result from CASTEP) to CHGCAR (VASP,can be opened by VESTA)

> qvasp -den2vasp

.res file to POSCAR

(res file is the structure file for GROMACS)

> qvasp -res2vasp

Symmetry analysis

qvasp -findsym prints the space group, the point group and the symmetry operations of a POSCAR, using the spglib library that is linked into the executable:

> qvasp -findsym POSCAR
 ============================================================

 ============================================================
  Input file   : POSCAR
  Symprec      :  1.00E-02
  Space group  : 14  (P2_1/c)
  Schoenflies  : C2h^5
  Point group  : 2/m
  N sym. ops.  : 4
  Lattice      : a=   7.77809  b=   8.36685  c=   9.17658  al/be/ga = (   90.00   89.86   90.00 ) deg
  4 symmetry operations -> SymOps.dat  (x' = W.x + w, fractional coords)
 ============================================================

The tolerance defaults to 1.0E-02 and can be overridden either as a bare number (qvasp -findsym 0.001, the v2.x syntax) or as the second argument (qvasp -findsym POSCAR 0.001). A stricter value is the right choice when a slightly distorted relaxation has blurred a symmetry; too small a value makes spglib report no symmetry and qvasp stops with spglib found no symmetry (symprec too small?). The operations are written to SymOps.dat as x' = W.x + w in fractional coordinates.

It is closer to actual surface model becuase the thickness of actual surface model are much thicker than the calculated model, and the atoms in deep layers are usually not change. 2. Special quasirandom structures (SQS)

A random alloy has no unit cell, so a DFT calculation has to replace it with a small periodic cell that reproduces the pair correlations of the random alloy as closely as possible. qvasp -sqs builds such a special quasirandom structure with an ATAT/mcsqs-style simulated annealing over the pair correlations, without needing ATAT.

The input is a structure file whose coordinate lines carry the composition annotation that ATAT uses, i.e. several elements separated by commas on the same site:

The three questions are the number of sites per disordered sublattice (0 = use the smallest cell that keeps the stoichiometry), the pair cutoff Rc in Angstrom and the number of annealing steps (empty = automatic). The tool warns you when the minimal cell is too small: four sites cannot represent a 25/25/25/25 mixture, which is why the default answer of 32 sites is used here and the cell becomes 2x2x2 = 64 atoms.

The output that matters is the Warren-Cowley parameter

\[\alpha_{ij} = 1 - \frac{p_{ij}}{x_j}\]

where \(p_{ij}\) is the probability of finding \(j\) next to \(i\) and \(x_j\) the concentration of \(j\). alpha = 0 means perfectly random, negative means ordering, positive means clustering. For this MgO-based cell all twenty pair parameters come out at 0.00000 over both shells, i.e. an exact random match, and the objective function reaches 0. That is the best possible outcome; when it does not reach zero, look at the table and increase the number of sites or Rc.

Note

SQS.vasp keeps the template lattice. For an alloy with a size mismatch you still have to relax the cell afterwards (ISIF = 3), and the pair correlation of the relaxed cell is not guaranteed to stay at zero.

Three answers are asked, in this order: the branch (1 = molecule/Gamma point, 2 = periodic solid), which imaginary mode to follow, and the displacement amplitude in Angstrom.

The amplitude is a physical displacement in Angstrom, not a dimensionless factor. VASP prints the eigenvector mass-weighted (e = u*sqrt(m)), so -freqfix de-mass-weights it with POMASS, normalises it, and then rescales it so that the largest atomic displacement equals the requested value. A typical amplitude is 0.05-0.2 A; the default 0.10 A is usually enough to leave the saddle point. The per-atom displacement table is written to freqfix.dat so the correction can be checked by hand, e.g. the last X coordinate becomes 2.226287 + (-0.316690) = 1.909597 A for a 0.10 A correction of the mode above.

band.dat gives you the energies. qvasp -bandp adds the orbital character: it reads EIGENVAL together with PROCAR and writes a table whose rows are (k, band) and whose columns are the projected weights of s, py, pz, px, dxy, dyz, dz2, dxz, x2-y2 and the total.

The single question restricts the projection to a subset of atoms – 1-2 for the two atoms of the primitive cell, empty for all of them – which is how you separate the contributions of two sublattices or of a slab and an adsorbate. The energies are shifted so that the Fermi level read from the OUTCAR sits at zero, and the high-symmetry labels are taken from the comments of the KPOINTS file, so neither KLABELS nor vaspkit is needed.

#     0.000000  G

Plot the columns against the first one, or filter on tot to draw a fat-band picture: the value in tot is the weight of the state on the selected atoms, so a band whose tot drops to zero along part of the path is a band that lives on the atoms you did not select.

Band unfolding for a supercell

A defect, an adsorbate or an alloy forces you to use a supercell, and then the bands of the supercell are folded into a small Brillouin zone that cannot be compared with the bands of the pristine primitive cell. qvasp -banduf implements the Popescu-Zunger unfolding and recovers an effective band structure (EBS) on the primitive-cell path.

It runs in two stages. Mode 1 prepares the supercell calculation:

> qvasp -banduf
Mode (1=setup, 2=postprocess) [enter=2] :  1

 Read transformation matrix from the TRANSMAT.in file if it exists.
   3  0  0   # must be three integers
   0  3  0   # must be three integers
   0  0  1   # must be three integers
 ...

Mode 1 writes transmatrix, KPOINTS_MAPPING_TABLE.in, POSCAR-super, KPOINTS-super and an optional KLABELS; run the supercell SCF and band calculation with those files. Mode 2 post-processes the finished run:

> qvasp -banduf
Mode (1=setup, 2=postprocess) [enter=2] :  2

 Transformation matrix accepted; supercell contains 9 primitive cell(s)

 k path: 103 KPOINTS rows, 99 unfolded path point(s)
 [qvasp WARNING] OUTCAR not found or no E-fermi line -- using Fermi = 0 eV!
                EBS energies are NOT shifted to the Fermi level.
 EIGENVAL: 103 k-points, 60 bands

 Unfolded 60 bands over 99 path k-point(s).

Here a 3x3x1 supercell of a 2-atom cell (18 atoms, 9 primitive cells) is unfolded along the K-GAMMA-M-K path of the primitive cell. The first few k-points of the supercell KPOINTS are the probe points that the mapping table needs; they are not part of the path and are skipped with a note.

EBS.dat has one block per k-point, and each block is a list of (k-distance, energy, weight) rows:

#KPT:1
   0.0000   -21.2493      0.0000

   ...

The third column is the spectral weight: a value near 1 means the supercell state is a good primitive-cell state at that k, and a value near 0 means it is a folded state that does not belong to the primitive band. Plot it as a scatter with the weight as the marker size or the colour, and the primitive bands reappear as bright lines even though the supercell has 9 times as many states.

Band Edges Positions

Band edges positions is crucial to the design photocatalyst, Schottky diode:

For 0D, 1D, 2D materials, we can add a parameter of LVHAR=.TRUE. in INCAR

when we calculate the band structre.

Then we can use “qvasp -wkd” to obtain the value of work funtion \(E_{wk}\).

If the vaccum energy level is set to 0 eV, the position of valence band maximum (VBM) is:

\(E_{VBM}\) = (-1) x \(E_{wk}\)

The conduction band minimum (CBM) can be calculated by:

\(E_{CBM}\) = \(E_{wk}\) + \(E_{bandgap}\)

The parameters of dipole correction (LDIPOL = .TRUE.; IDIPOL = 3; DIPOL =0.5 0.5 0.5) should be condiered if the calculated system contain dipole moment.

For 3D materials, two method are usually used:

  1. Cleave a surface and obtain the workfunction as aforementional discussions.

  1. Using the deep energy level to align the CBM and VBM between different materials (set ICORELEVEL=2 in INCAR)

Thermal corrections: H(T), S(T) and G(T)

The zero point energy is the T = 0 limit of the vibrational free energy. At a finite temperature the harmonic partition function also contributes to the enthalpy and to the entropy, and those are what you need to compare an adsorption energy with an experiment or to build a phase diagram. “qvasp -thermo” computes them:

The two modes answer different questions:

  • Surface adsorbate (mode 2, the default) keeps only the vibrational contribution. The translational and rotational degrees of freedom of an adsorbate are not free — they are frustrated — so adding them would double-count the modes that the frequency calculation already found.

  • Gas molecule (mode 1) adds translation, rotation, the electronic entropy and the PV term, and therefore also asks for the pressure, the spin multiplicity and the rotational symmetry number. It decides between the linear and the non-linear rotor from the number of modes.

Two details are worth knowing because they are easy to trip over:

  • Imaginary modes are skipped, not clamped. A frequency that came out as f/i has no harmonic partition function; including it would give a complex free energy. The warning tells you how many were dropped, and if that number is large the structure is not a minimum and the correction means nothing.

  • Only the entropy is clamped, and only below 50 cm-1. A very low real frequency has a large entropy that diverges as the frequency goes to zero, so the entropy uses 50 cm-1 as a floor. The ZPE and H(T) keep the raw frequency, because the harmonic oscillator energy is well behaved there. For this example the entropy would be 86.56 instead of 40.31 J/(mol*K) without the clamp, and G would be off by 0.14 eV.

How the interpolation works, because it is the part that decides the accuracy:

  • gcut = 0 (the default) uses the complete-grid basis. All 4096 plane-wave-like Fourier functions of the 16x16x16 mesh are used (1 + 2x2044 pairs + 7 half-grid cosine terms), so the fit reproduces the computed eigenvalues to machine precision at the mesh points. A finite gcut truncates to a sphere around the origin and leaves a 0.2-0.3 eV error at the band edges; it is offered for a quick look, not for production.

  • The Tikhonov parameter lambda shrinks the high-frequency coefficients (weight \(1/(1+\lambda|R|^2)\)) to suppress ringing where the mesh is undersampled. lambda = 8 is calibrated on silicon: lambda = 0 biases the p-type conductivity by up to +30%, lambda >= 16 over-regularizes and flattens the band edges.

  • The velocity operator uses real-space lattice vectors \(R = g\cdot A\). An earlier version used the reciprocal vectors, which biased sigma by -46% to -76%; that is fixed, and the residuals printed above are the evidence that the fit is now consistent.

The two residual lines are the quality control you should read first: the worst band over the whole fit (7.0e-2 eV for band 38, which is a high unoccupied band with a strong dispersion) and the worst band near the Fermi level (3.9e-2 eV). If the near-EF residual is larger than the thermal energy \(k_BT\) (26 meV at 300 K), the k-mesh is too coarse for the temperature you asked for.

The relaxation time is the one external parameter. CRTA assumes a single constant \(\tau\) with no energy or temperature dependence, so sigma and therefore ZT scale linearly with it. Calibrate it from an experimental mobility (\(\tau = \mu m^*/e\)) or take the same value as the reference calculation you are comparing with; 10 fs is a typical starting point for a heavily doped semiconductor at room temperature.

Accuracy. For silicon this implementation agrees with BoltzTraP2 26.3.1 (the reference implementation of the same method, 81x81x81 FFT mesh) within -6.6% to +4.4% on sigma and +-12.8% on S over the n-type range -5 to -100 x 10^19 cm^-3. For p-type heavy doping the deviations are about +-10% on sigma and +-18% on S, and for p-type light doping sigma is 20-32% too high and S is 21-29% too low: the top of the valence band of silicon has degenerate heavy and light hole bands with a very steep curvature, and the complete-basis interpolation and the star regularization of BoltzTraP2 handle that region differently. A finer mesh (96x96x96) only improves it marginally, so this is a property of the method, not a bug. For quantitative p-type light-doping work use BoltzTraP2 or the experiment.

Note

eta is the resolution of the energy histogram used for the DOS integration (the box width is eta/2), not a Gaussian broadening. For a sharply structured band edge reduce it to 0.01-0.02 eV. With kappa_L mode = 0 the last two columns stay at zero and only the electronic part is computed; mode 1 takes a manual kL(300 K) and mode 2 uses the Slack model.

Optical Property

The absorption spectrum is significant for the photovoltaic device and photocatalyst.

The linear optical properties can be obtained from the frequency-dependent complex dielectric function \(\varepsilon(\omega)\)

\[\varepsilon(\omega)=\varepsilon_{1}(\omega)+i \varepsilon_{2}(\omega),\]

where \(\varepsilon_{1}(\omega)\) and \(\varepsilon_{2}(\omega)\) are the real and imaginary parts of the dielectric function, and \(\omega\) is the photon frequency.

The frequency-dependent linear optical spectra, e.g., refractive index \(n(\omega)\), extinction coefficient \(\kappa(\omega)\), absorption coefficient \(\alpha(\omega)\), energy-loss function \(L(\omega)\), reflectivity \(R(\omega)\) can be calculated from the real \(\varepsilon_{1}(\omega)\) and \(\varepsilon_{2}(\omega)\) parts [See Ref. A. M. Fox, Optical Properties of Solids]:

\[n(\omega)=\left[\frac{\sqrt{\varepsilon_{1}^{2}+\varepsilon_{2}^{2}}+\varepsilon_{1}}{2}\right]^{\frac{1}{2}}\]
\[k(\omega)=\left[\frac{\sqrt{\varepsilon_{1}^{2}+\varepsilon_{2}^{2}}-\varepsilon_{1}}{2}\right]^{\frac{1}{2}}\]
\[\alpha(\omega)=\frac{\sqrt{2} \omega}{c}\left[\sqrt{\varepsilon_{1}^{2}+\varepsilon_{2}^{2}}-\varepsilon_{1}\right]^{\frac{1}{2}}\]
\[L(\omega)=\operatorname{Im}\left(\frac{-1}{\varepsilon(\omega)}\right)=\frac{\varepsilon_{2}}{\varepsilon_{1}^{2}+\varepsilon_{2}^{2}}\]
\[R(\omega)=\frac{(n-1)^{2}+k^{2}}{(n+1)^{2}+k^{2}}\]

Magnetic ground state, exchange parameters and Curie temperature

The magnetic suite “qvasp -magm” provides six sub-tools for magnetic materials. A typical workflow runs as follows (the example of graphitic carbon nitride g-C4N3 can be found in Examples/Tools/magm, see Du, Sanvito and Smith, Phys. Rev. Lett. 108, 197207 (2012)):

  1. Initialize MAGMOM from a finished spin-polarized run:

> qvasp -magm
 1) spinden : spin density and magnetic moment from CHGCAR
 2) magconf : generate FM/AFM/FIM magnetic configurations
 3) fitj    : exchange parameters J from total energies
 4) curie   : Curie/Nel temperature (Monte Carlo + mean field)
 5) mae     : magnetocrystalline anisotropy energy (SOC)
 6) maginit : initialize MAGMOM from OUTCAR
Choose: 6

The tool reads the magnetization table of OUTCAR (run with LORBIT = 11), rounds the moments to integers, writes “MAGMOM = …” into INCAR (a backup of the old INCAR is kept as INCAR.bak-magmom), and prints the per-atom magnetic moments.

(2) Generate the competing spin configurations with sub-option 2 (magconf). It creates FM/AFM/… INCARs (or appends run-length MAGMOM lines) according to the magnetic atoms that you select. Perform static calculations (NSW = 0, same geometry!) for every configuration and read their total energies.

(3) Map the total energies onto the Heisenberg model with sub-option 3 (fitj). Prepare one folder per configuration containing the OUTCAR, feed the folder names one per line, select the magnetic atoms, and give the distance cutoffs of the exchange shells (from the pair-distance table printed on the screen). fitj least-squares fits E = E0 - sum J_n*C_n and writes J_table.dat with the coordination numbers and J_n (meV).

(4) Estimate the ordering temperature with sub-option 4 (curie). It reads J_table.dat, runs a classical Heisenberg Monte Carlo on the provided cell to locate the chi(T) peak (Tc), and also prints the mean-field estimate kB*Tc = (2/3)*J0*S(S+1).

(5) The magnetocrystalline anisotropy energy (sub-option 5, mae) compares the SOC total energies of the x/y/z spin directions (three runs with MAGMOM/SAXIS along x, y, z; magm generates the three INCARs) and writes mae.dat.

(6) Sub-option 1 (spinden) integrates the spin density of CHGCAR inside Bader-like atomic basins, printing the net magnetic moment per atom and in total.

Real-data example: g-C4N3 (validated output). The complete chain has been validated on real VASP 6.5.1 data for graphitic carbon nitride g-C4N3 (28-atom 4xC4N3 cell, ENCUT 500 eV, Gamma 3x3x1, 36-core runs; reference: Du, Sanvito and Smith, Phys. The intensity of mode m is I = sum_alpha |sum_{a,beta} Z*_{a,alpha beta} e_{a beta}(m)|^2, where Z* are the Born charges (vasprun.xml) and e the mass-weighted eigenvectors (OUTCAR). The outputs are the mode table ir.dat and the broadened spectrum ir_spectrum.dat. Silent (non-polar) modes give zero intensity, which is a quick sanity check of the workflow.

The broadened spectrum uses a Gaussian with the requested FWHM by default (the same FWHM means sigma = FWHM / 2 sqrt(2 ln 2)); answer L at the lineshape prompt for the lifetime (Lorentzian) line shape. Lorentzian tails decay only as 1/Delta^2, so a strong mode leaves visible intensity tens of cm-1 away; Gaussian tails are negligible and normally look closer to a measured spectrum.

Choosing the lineshape

A Gaussian broadening (the default, sigma = FWHM / 2 sqrt(2 ln 2)) mimics an instrument resolution: its tails are negligible, so a single mode stays a single peak.

A Lorentzian is the physical homogeneous (lifetime) line shape, selectable with L, but its tails decay only as 1/Delta^2: with FWHM = 10 cm-1 a mode at 1292 cm-1 still gives I/I_peak = (FWHM/2)^2 / (Delta^2 + (FWHM/2)^2) = 25/(47.3^2+25) = 1.1 % at 1339 cm-1, i.e. 25.6 for a peak of 2317. That is mathematically correct, not a broadening error, but it can look like a spurious shoulder. Comparison on the diamond example:

Frequency fix (imaginary modes)

qvasp -freqfix (the old -zc name still works) removes imaginary frequencies. Two modes are offered:

  1. molecule / Gamma point – reads the soft-mode eigenvector printed by VASP after the dynamical-matrix diagonalisation. The eigenvector is mass-weighted (e = u*sqrt(m)), so it is de-mass-weighted with the POMASS values, normalised and then scaled to a physical amplitude (default 0.10 A, the largest atomic displacement). The corrected structure goes to POSCAR, the old one to POSCAR-bak, and the per-atom displacement vectors to freqfix.dat. All imaginary modes are listed, so the strongest one (or a chosen one) can be followed. Rerun the relaxation and the frequency calculation afterwards.

  2. periodic solid – reads the phonopy FORCE_CONSTANTS (header: n_primitive n_supercell) and imposes the acoustic sum rule, Phi(i,i) = Phi(i,i) - sum_j Phi(i,j). It prints the maximum |sum_j Phi(i,j)| before and after and writes FORCE_CONSTANTS_asr.

Surface energy

Prepare one folder per slab (each with OUTCAR/POSCAR or CONTCAR) plus a bulk reference folder, then:

> qvasp -esurf
Bulk reference folder (OUTCAR+POSCAR) [enter=bulk] :
How many slab folders [enter=3] : 3
Slab #1 folder [enter=slab] : slab4
  layers N (for the 1/N fit, 0=skip) : 4
...

gamma = (E_slab - N*mu_bulk)/(2A) is reported per slab in eV/A^2 and J/m^2 (esurf.dat). When the layer number N is given for every slab, a linear fit of gamma versus 1/N is performed and the intercept (N -> inf) is printed as the extrapolated surface energy of the bulk-truncated surface.

NEB endpoints and defect sites

“qvasp -neb POS1 POS2” aligns two endpoint structures for NEB: atoms are paired by nearest-neighbour matching (PBC aware), the second endpoint is reordered accordingly, and the interpolated images are generated (folders 01, 02, … between the endpoints).

“qvasp -defect POSCAR” lists the symmetry-inequivalent sites of the cell (spglib), so that a single representative defect/doping calculation per orbit is enough. The inequivalent sites are printed with their Wyckoff-like labels and fractional coordinates.
